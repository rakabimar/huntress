# Role-action methodology

Build the smallest role-action-context matrix from configured accounts and feature documentation. Select one allowed high-role cell and its expected lower-role denial. Capture both at the authoritative server operation, not the UI. Then vary one enforcement path—method, version, route, job, delegation state, or permission lifecycle.

For inherited/temporary roles, record permission provenance and test after grant, expiry, and revoke as separate hypotheses. For impersonation, preserve actor versus represented-user identity and audit restrictions. Support requires completion of the capability or durable permission acquisition.
