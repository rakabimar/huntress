# Authorization differential methodology

Create controlled objects in the required tenant/relationship states. Record intended visibility, then choose exactly one matrix cell. Baseline with the authorized principal and replay the identical method, locator, fields, and object under the unauthorized principal. For writes, read the authoritative state afterward; for jobs/exports, follow ownership through artifact retrieval.

If a request changes both principal and identifier, results are ambiguous. If the application masks denial as 404, compare protected content/postcondition rather than status. Expand to nested, bulk, version, GraphQL, or lifecycle siblings only after one invariant creates a justified lead.

The falsifiable statement must name the tuple and effect. Refutation includes documented sharing/delegation, per-item filtering, uniform service-layer denial, unchanged state, or an object that was never private.
