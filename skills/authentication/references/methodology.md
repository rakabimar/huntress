# Identity-transition methodology

Choose one authentication state transition and one binding. Create controlled accounts/channels, capture successful owner behavior and a failing mismatched control, then substitute only account, browser transaction, factor, channel, endpoint, lifecycle state, or token purpose.

Record token metadata/fingerprint rather than value. Verification, reset, magic, and MFA artifacts should be tested for subject, transaction, purpose, expiry, single use, and invalidation individually. Account linking must test issuer+subject to local-account binding and recent re-authentication. Support requires wrong-account authentication or a materially weakened protected recovery/step-up transition.
