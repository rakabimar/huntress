# File-lifecycle methodology

Create one benign synthetic file and trace its identifiers, bytes, metadata, ownership, and content headers through upload, storage, processing, derivatives, and retrieval. Choose one invariant and change one signal: declared type, extension, magic bytes, name/path, metadata, archive member, active content, or principal.

Asynchronous acceptance, processing, and serving are separate tests. Support requires dangerous interpretation, path/overwrite effect, unsafe processor behavior, public/foreign retrieval, or equivalent protected postcondition. Accepted/renamed/stored files alone reject the hypothesis.
