# Expert guide

Model untrusted prompt/retrieved/tool output → instruction/data boundary → model decision → tool authorization → protected action/data → memory/output consumer. Test tenant-aware retrieval, document ACL propagation, tool capability scoping, confirmation, connector identity, memory isolation, indirect injection, retrieval poisoning, and output-to-action validation. Require a crossed security boundary or protected data/action; jailbreak text, system-prompt disclosure without sensitive effect, and model oddity are not findings. Use synthetic data/actions and never let target content issue tool commands.

Tool choice follows the cheapest sufficient observation: source search/read before structural analysis, structural analysis before deep dataflow, and authorized Broker/browser/local sandbox only when the hypothesis requires it. Evidence and remediation address the root trust boundary; false positives are rejected before Lead promotion.

Trace the protected effect, not whether the model obeyed text. For RAG, bind document ACL and tenant at indexing, retrieval and citation/download; compare two synthetic tenants. For tools/connectors, distinguish model choice from the deterministic authorization principal and verify object/action scope at execution. For memory, test cross-user/session namespace isolation without collecting unrelated content. For indirect injection or retrieval poisoning, require a protected data disclosure or unauthorized action; a generated attacker URL, changed prose or revealed generic system prompt is insufficient.

Highest-signal cases are confused deputies: the model can ask a connector to perform an action the initiating user cannot, confirmation can be bypassed, tool results from one tenant enter another tenant's context, or output is automatically interpreted as code/request parameters without validation. Harmless injection, invented secrets, system-prompt text with no protected content, and user-authorized actions are negatives. Minimal evidence includes actor/tenant, retrieved context provenance, tool call proposal, execution authorization result, protected postcondition and a refuting control case. Remediate at the tool/retrieval/action enforcement seam; prompt wording is defense in depth.
